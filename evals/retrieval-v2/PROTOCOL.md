# Folio retrieval-v2: frozen evaluation protocol

This is a new, source-grounded retrieval set. It preserves all v1 development cases, held-out cases, freeze records and results. It contains no evaluation outcomes. The first retrieval run is blocked until the engineering lead and independent source reviewer accept this package and its exact hashes. The implementation task receives the schema and protocol, not these questions or gold support.

## Decision and predeclared case design

The decision is whether the current lexical, local latent and hybrid retrieval modes can locate the physical source pages needed for 24 new questions over the three already pinned NIST documents. The balance was declared before case serialization and before retrieval: eight questions per document, each with three direct definitions/facts, three procedural actions, and two nearby-concept comparisons (nine direct, nine procedural, six nearby overall). These labels describe question intent, not measured difficulty. Nearby means comparing related concepts that are distinguished in a source passage; it does not assert semantic generalization or an independent distractor benchmark.

Questions and short support excerpts were authored from only the three prepared texts in `data/prepared/manifest.json`. Excerpts are literal substrings, retaining extraction newlines, ligatures, hyphenation and footnote markers. Pages are 1-based physical PDF pages, as declared by `data/prepared/preparation.json`, and are not printed page numbers. Every question has one gold physical page. Three comparisons use multiple short excerpts on that same page. Selection was purposive and based on source passages; no project search index, retrieval ranking, answer generator, embedding service or application-model endpoint was invoked during authoring. A literal string/page/hash check is source validation, not a retrieval evaluation.

These are versioned technical publications used as a document corpus, not a survey of current policy or regulatory/compliance advice. This pass did not re-download PDFs, verify current revisions/corrections/retractions, or repeat extraction. Original PDF hashes in the freeze are the source hashes declared by the pinned prepared manifest; prepared text and algorithm files were independently hashed locally. The AI RMF robustness definition is quoted there with attribution to ISO/IEC TS 5723:2022; do not attribute that wording as an original definition written for this project. Upstream rights and third-party caveats remain governed by the project's existing `DATA_SOURCES.md` and upstream records. These cases and answer keys are published for reproducibility after the first evaluation.

## Frozen evaluation procedure (not yet run)

Use a clean isolated evaluation database populated with exactly the three original active prepared documents, preserving their IDs and original text. Do not use a personal runtime database, changed/deleted/replacement documents or extra demo documents. Record the prepared corpus, algorithm, lockfile/runtime versions, platform and runner hashes, resulting document/chunk counts and actual run UTC before reporting results. Abort on a source/preparation/algorithm hash mismatch; do not silently refresh pins.

Run the exact unmodified `query` string once per mode (`lexical`, `latent`, `hybrid`), each with `limit=5` and the full three-document search scope: 24 cases times three modes, 72 planned retrieval requests. Gold `document_id`, `pages`, `support` and `category` are grading fields only, never query filters, search text or retrieval hints. Use the same corpus/configuration for all modes and preserve returned ordering. Do not call the answer or model bridge endpoints. Log actual zero model attempts before and after rather than infer it from intent. One request per query/mode is sufficient for this deterministic ranking comparison; observed wall times are descriptive single-run measurements, not a latency benchmark or cost estimate.

Primary metrics are page Hit@5 and page MRR@5. A hit requires the correct document ID and the gold physical page in the first five returned chunks. Hit@5 is one for any qualifying chunk and zero otherwise; MRR@5 is the reciprocal rank of the first qualifying chunk, otherwise zero. Multiple chunks on the same page do not create extra credit. Keep every one of the 24 cases in each mode's denominator. Empty results, request failures and missing cases score zero and must also be reported separately; an incomplete run cannot be called complete. Report all per-case first-match ranks and aggregate means per mode, per document (n=8) and per category (n=9/9/6); do not pool modes into a single accuracy figure. The overall document-balanced macro mean equals the overall case mean because each document has eight cases.

A page hit is a location proxy: it does not establish that the returned chunk covers all support excerpts, that an answer is correct, or that citations fully entail an answer. This set measures retrieval only. No answer quality, hallucination rate, security, live-model quality, causation or general accuracy conclusion is supported by it. Keep v1 and v2 results separately labeled, including their denominators; do not replace or repair v1 results using this set.

## Freeze and leakage controls

The exact case wrapper is `{cases: [{id, query, document_id, pages, support: [{page, excerpt}], category}]}`. Case IDs and order are stable. `FREEZE.json` pins exact case/protocol/source-check bytes, prepared manifest and preparation metadata, original PDF hash declarations and both current retrieval algorithm files. It records actual UTC at freeze after authoring. `SOURCE_CHECK.json` records exact substring offsets and hashes; it has no rankings or answers beyond the permitted support key. Its checks are source mechanical checks, not test or evaluation results.

The case-authoring, supervising lead and independent case-review roles may inspect the proposed questions/support before the first run. The runner implementation context must exclude these cases and support keys. The case author read only legacy/development question strings for exact-duplicate exclusion; no legacy retrieval results or answer judgments were used to select v2 cases. There are no exact query duplicates with those 16 prior questions. The corpus and related concepts are shared with prior work, so this is not a guarantee against model training exposure or broad semantic overlap. Cases on the same page and concept are correlated; do not treat 24 examples as statistically independent evidence or attach unsupported population estimates/confidence claims.

No tuning of questions, gold support, corpus, ranking or mode parameters is allowed after the first evaluation to improve the reported score. Corrections before evaluation require a new explicit freeze preserving the superseded freeze and a fresh independent review; report any later correction with its reason and preserve original results. Do not infer acceptance merely from successful schema/hash checks. The lead records reviewer acceptance separately before authorizing the first run.
